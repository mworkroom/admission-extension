# Phase 4 계획서 — 실사용 기록과 여러 페이지 작업

## 1. 목적

실제 입학요강 작성 중 한 과정의 여러 페이지에서 확인한 값을 하나의 활성 작업에 합치고, 추출 실패·수정·복사 기록을 별도 표 없이 남긴다. 반복되는 실패만 후속 adapter 개선 근거로 사용한다.

현재 구현 상태:

- P4-0 알려진 상담 위젯 숨김 완료
- P4-1 활성 과정 작업 데이터 계약 완료
- P4-2 현재 페이지 추가와 여러 출처 병합 완료
- P4-3 수정·복사·실패 기록 완료
- P4-4 내보내기와 반복 실패 요약 완료
- P4-5 자동 검사·저장 실패·430px 로컬 회귀 완료
- 현재 확장 버전: `0.12.0`
- 다음 작업: P4-5 실제 Chrome 수동 검증

## 2. 원칙과 제외 범위

- 모든 작업 데이터는 `chrome.storage.local`에만 저장한다.
- 현재 사용자가 연 활성 탭에서만 읽고 동작한다.
- 새 권한과 광범위한 host permission을 추가하지 않는다.
- 현재 페이지 원문과 출처를 유지하고 값을 추측하거나 자동 덮어쓰지 않는다.
- 전체 대학 사이트 크롤링, 로그인 페이지, CAPTCHA, Word·Notion 연동은 포함하지 않는다.
- 상담 위젯은 네트워크 요청을 차단하지 않고 화면 요소만 숨긴다.
- 위치·크기·`position: fixed` 같은 일반적인 모양으로 임의 요소를 숨기지 않는다.

## 3. 단계별 작업

### P4-0 — 알려진 상담 위젯 숨김

- [x] 저장 가능한 `상담 위젯 숨기기` 설정
- [x] 기본 활성화와 Side Panel 내 즉시 해제 토글
- [x] Unibuddy의 확인된 id·iframe 주소·title 서명만 대상으로 지정
- [x] 현재 탭에 CSS 규칙 적용·해제
- [x] 중복 적용을 방지하고 적용 실패가 페이지 분석을 막지 않게 처리
- [x] 권한 추가 없음
- [x] 자동 검사와 430px 로컬 UI 검증
- [x] 실제 Chrome `0.8.0`에서 QMUL 위젯 숨김 확인

새로운 공급자는 실제 페이지 DOM에서 안정적인 공급자 서명을 확인한 뒤 규칙을 추가한다. 학교별 임시 위치 selector나 추적 URL 전체값은 사용하지 않는다.

### P4-1 — 활성 과정 작업 데이터 계약

- [x] 한 번에 하나의 활성 과정 작업 schema 정의
- [x] 학교, 과정, 학년도, 입학 회차와 출처 페이지 목록 저장
- [x] 현재 분석 결과와 수동 수정값의 출처 구분
- [x] 손상 데이터 격리와 schema version 보호

저장 키는 `activeCourseWork`, schema version은 `1`이다. 활성 작업 id는 학교, 정확한 과정 URL에서 분리한 과정 키, 학년도, 입학 연월, 수학 형태와 fee status를 조합한다. KCL Requirements·Fees는 같은 과정 키로 묶고 SOAS·QMUL·Manchester도 지원 과정 URL의 정확한 slug만 사용한다.

11개 항목은 각각 복수의 값 entry와 선택된 entry id를 가질 수 있다. entry의 `origin`은 `analysis` 또는 `manual`이며, 분석값은 작업의 공식 출처 페이지 목록에 등록된 HTTPS URL을 반드시 가리킨다. 수동값은 출처가 없더라도 실제 입력값을 필수로 보존한다.

손상된 현재 작업은 사용할 수 있는 상태에서 제외하되 저장 원본을 자동 덮어쓰지 않는다. 알 수 없는 미래 schema도 빈 작업으로 변환하거나 저장하지 않는다.

### P4-2 — 현재 페이지 추가와 여러 출처 병합

- [x] 현재 페이지 분석 결과를 활성 작업에 추가
- [x] 같은 값은 출처만 합치고 중복 생성하지 않기
- [x] 다른 값은 기존 값과 새 값을 함께 보이는 충돌 상태로 저장
- [x] 다른 과정 페이지를 잘못 합치지 않도록 확인 단계 제공

분석 결과 안의 `활성 과정 작업` 상자에서 현재 분석으로 새 작업을 시작하거나 같은 작업에 추가한다. 같은 값은 하나의 entry를 유지하면서 공식 출처 참조만 합치고, 다른 실제 값은 두 entry를 모두 보존한 뒤 자동 선택을 해제해 충돌 항목으로 집계한다.

현재 분석의 과정 키 또는 입학 기준이 기존 활성 작업과 다르면 직접 병합하지 않는다. 기존 작업과 새 작업의 과정명·입학 기준을 native dialog에서 비교하고, 기본 초점을 취소에 둔 뒤 명시적으로 `교체하고 시작`한 경우에만 새 활성 작업으로 교체한다.

저장 성공 전에는 화면과 메모리의 기존 작업을 바꾸지 않는다. 저장 실패 시 dialog 또는 활성 작업 상자에 오류를 표시하고 기존 작업을 유지한다.

### P4-3 — 수정·복사·실패 기록

- [x] 직접 입력과 수정 기록
- [x] 항목별 복사 기록
- [x] 추출 성공·실패와 reason code 기록
- [x] 사이트 구조, 별도 페이지, 지원서 확인 필요를 구분

활성 작업과 현재 분석이 같은 과정·입학 기준일 때 각 항목 카드에 `활성 작업 값`을 표시한다. 페이지 분석 entry를 지우지 않고 직접 확인한 값을 새 `manual` entry로 추가해 선택하며, 이후 수정도 이전 manual entry를 보존한 채 새 entry와 수정 기록을 함께 저장한다. University와 Course는 활성 작업 식별자를 바꾸는 값이므로 직접 수정 대상에서 제외한다.

실사용 기록은 별도 로컬 키 `activeCourseWorkEvents`에 schema version 1로 최대 1,000개를 저장한다. 분석 한 번마다 11개 항목의 성공·실패, extraction status, reason code, 출처와 값 snapshot을 남기고, 현재 페이지 값·확인한 사항·활성 작업 값 복사 성공과 실패도 항목별로 기록한다. 직접 입력값과 생성·수정 기록은 하나의 storage 쓰기로 저장해 일부만 반영되지 않게 한다.

추출 결과는 원문 값·상세 설명·다음 행동을 함께 보고 분류한다. 별도 안내 페이지가 필요한 경우 `separate_page`, 지원서나 application form 확인이 필요한 경우 `application_check`, 그 밖에 현재 사이트 구조에서 찾지 못한 경우 `site_structure`로 기록한다. 원래 reason code가 없으면 분류에 맞는 명시적 code를 보완한다. 손상된 실사용 기록은 읽기 시 격리하고 새 기록 저장으로 원본을 덮어쓰지 않는다.

### P4-4 — 내보내기와 반복 실패 요약

- [x] 활성 과정 JSON 내보내기
- [x] 실사용 기록 CSV 내보내기
- [x] 학교·항목별 반복 실패 요약
- [x] 다음 adapter 개선 후보를 기록에서 결정

활성 작업 JSON은 내보내기 형식과 schema version, 내보낸 시각, 전체 `activeCourseWork`를 보존한다. 실사용 기록 CSV는 Windows·Excel에서도 바로 열 수 있도록 UTF-8 BOM과 CRLF를 사용하고, 14개 고정 열에 extraction·manual·copy 기록의 출처와 값 snapshot을 포함한다. Blob과 임시 download link를 사용하므로 `downloads` 권한은 추가하지 않는다.

반복 실패는 `siteKey + fieldKey`로 묶어 실패 횟수, 서로 다른 과정 수와 실패 분류별 횟수를 표시한다. 같은 페이지를 여러 번 분석한 것만으로 adapter 후보가 되지 않도록 `site_structure` 실패가 3회 이상이고 서로 다른 과정이 2개 이상일 때만 `다음 adapter 개선 후보`로 표시한다. `separate_page`와 `application_check`는 업무상 후속 확인 위치로 요약하지만 adapter 결함으로 자동 분류하지 않는다.

실사용 기록을 읽지 못하면 CSV와 요약을 비활성화하고, 손상 기록은 요약·CSV에서 제외했다는 사실을 표시한다. 내보내기는 저장 데이터를 변경하지 않는 읽기 전용 동작이다.

### P4-5 — 전체 검증

- [x] 저장 실패 시 기존 활성 작업 유지
- [x] KCL·SOAS·QMUL·Manchester 자동 회귀
- [x] 430px Side Panel UI 회귀
- [ ] 실제 Chrome에서 여러 페이지 작업과 저장 유지 확인

자동 검사 106개와 430px 로컬 UI harness에서 작업 시작·직접 입력·실사용 기록 저장 실패, 다른 과정 교체 취소·확정, 네 학교 11개 카드와 가로 넘침 없음을 확인했다. KCL SOP의 확인된 원문에 `online application form`이 포함되어도 지원서 확인 실패로 잘못 분류하지 않도록 `0.11.1`에서 보강했다. 실사용에서 발견된 Alliance MBS URL 미지원 문제는 `0.12.0`에서 Manchester 과정 탭과 여섯 공식 보조 페이지를 합치는 adapter로 해결했다. 실제 Chrome에서 Manchester 공식 페이지 DOM과 추출 패턴을 확인했지만, 확장 관리 화면과 Side Panel 동작은 자동 제어할 수 없어 `docs/qa/PHASE_4_CHROME_CHECKLIST.md`의 수동 검증이 남아 있다.

## 4. 완료 기준

- 한 과정의 여러 공식 페이지 결과를 출처와 함께 하나의 활성 작업에 합친다.
- 충돌값을 자동 선택하지 않고 비교 상태로 보존한다.
- 직접 입력, 수정, 복사와 실패가 실제 사용 흐름에서 자동 기록된다.
- 반복 실패를 학교·항목·원인별로 확인해 다음 개선 대상을 결정할 수 있다.
- 손상 데이터와 저장 실패가 기존 작업을 훼손하지 않는다.
- 권한을 추가하지 않고 KCL·SOAS·QMUL·Manchester 자동·430px·실제 Chrome 검증을 통과한다.

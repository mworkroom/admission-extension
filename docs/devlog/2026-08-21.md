# 2026-08-21 Admission Extension Development Log

## Work Summary

실제 확장에서 확인한 17개교 28개 과정의 V2.5 테스트 결과를 기존 Tuition Fee v2와 대조했다. 학교명 예외를 추가하지 않고 Manchester의 audience 연결, Sheffield의 할인액 오인, UCL의 수학 형태 class, Birmingham의 국가 선택, Edinburgh형 연결 학비 페이지처럼 반복 가능한 DOM 계약을 보정했다.

## Work Completed

- CSV의 실제 테스트 행만 분리해 필드별 성공·실패 문구와 Tuition Fee 실패 유형을 집계했다.
- 실제 렌더링 DOM에서 Manchester, Sheffield, UCL, Birmingham, Edinburgh의 대표 실패를 재현했다.
- 금액 블록의 audience 라벨 배치 방향과 가장 가까운 수학 형태를 각각 연결하도록 수정했다.
- 금액만 있는 작은 카드 노드에만 부모 문맥을 보충하고, `study-mode` class 기반 Full-time·Part-time 금액을 Card/Container 계열에 포함했다.
- `save up to`, saving, fee waiver·reduction을 장학금·할인으로 분류하고 `Fees and funding`의 일반 funding 문구가 학비를 오염시키지 않게 했다.
- fee 전용 국가 select에서 South Korea를 선택하는 공통 adapter와 비동기 갱신 대기를 추가했다.
- 공식 연결 페이지 읽기를 공통 cache로 통합하고, 현재 기준에 맞는 직접 학비 후보가 없을 때 연결 페이지를 재시도하도록 변경했다.
- staged admissions 표의 첫 `Application received by`, `All applicants` 기간 종료일, 명시적인 no-closing-date 상태를 구조화했다.
- CV 수동 확인 선택지에 `공통`을 추가했다.
- Manchester prefix audience, Sheffield fee box·할인, UCL class 기반 수학 형태, Birmingham 국가 선택, staged table, 공통/no-closing deadline fixture와 회귀 검증을 추가했다.
- 전체 `npm.cmd run check`에서 98개 테스트가 모두 통과했다.

## Decisions

- Manchester의 학과별 차이는 학교 단일 예외로 묶지 않고 각 페이지가 사용하는 구조와 라벨 방향으로 판정한다.
- 직접 금액과 연결 페이지가 동시에 있을 때 단순히 직접 후보 존재 여부로 중단하지 않고, 현재 학년도·International·수학 형태 기준과 맞는 직접 후보가 있는지로 후속 조회를 결정한다.
- staged admissions에서 최종 마감일보다 첫 stage가 실제 업무에 유용하다는 테스트 의견을 반영해 표의 첫 지원 접수 마감일을 우선한다.
- Entry Requirements와 지원 서류 누락은 Tuition Fee와 다른 경계 문제이므로 이번 수정에 학교별 임시 규칙으로 섞지 않는다.

## Work Summary - 메모 외부 백업과 복원

확장 재설치 후 `chrome.storage.local`에만 있던 수동 메모가 삭제된 문제를 계기로, 메모를 확장 저장소 밖의 JSON 파일로 내보내고 복원하는 기능을 추가했다.

## Work Completed - 메모 외부 백업과 복원

- 도구 dialog에 `메모 백업 내보내기`와 `메모 백업 가져오기`를 추가했다.
- 내보내기는 메모 수, 형식 버전, 내보낸 시각과 전체 schema 2 저장소를 `admission-memos-YYYY-MM-DD.json`에 기록한다.
- 가져오기는 형식과 모든 레코드를 검증한 뒤 현재 저장소와 병합한다.
- 같은 ID의 메모는 `updatedAt`이 더 최신인 경우에만 갱신하고, 현재 메모와 백업에만 있는 다른 메모는 모두 보존한다.
- 손상된 JSON, 다른 형식, 5MB 초과 파일은 저장소에 적용하지 않는다.
- 왕복 백업, 손상 파일 거부, 최신 기록 병합과 Side Panel UI 연결 회귀 테스트를 추가했다.

## Decisions - 메모 외부 백업과 복원

Chrome 공식 문서상 `storage.local`은 확장 제거 시 삭제된다. `storage.sync`는 동기화가 꺼지면 local처럼 동작하고 전체 약 100KB·항목당 8KB 제한이 있어 장문 메모의 유일한 백업으로 사용하지 않았다. 별도 파일을 복구 기준으로 삼고, 가져오기에서는 현재 기록을 일괄 덮어쓰지 않는 병합 정책을 적용했다.

## Current Status - 메모 외부 백업과 복원

구현과 자동 테스트를 완료했다. 이미 확장 제거로 삭제된 과거 local 메모는 이 기능만으로 복구할 수 없다. 설치된 확장에서 실제 다운로드와 파일 선택 복원은 확장 재로드 후 확인이 필요하다.

## Next Steps - 메모 외부 백업과 복원

- 확장을 다시 로드한 뒤 테스트 메모를 내보내고, 삭제 후 같은 파일로 가져와 복원되는지 확인한다.
- 중요한 메모가 쌓인 뒤 또는 확장을 제거하기 전에 최신 JSON을 별도 폴더에 보관한다.
